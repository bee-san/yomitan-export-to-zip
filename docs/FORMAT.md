# Export format, what is preserved, and what is lost

This page documents the input format the converter reads, how each field is
mapped back to a Yomitan dictionary archive, and the information that either
the export itself or a standalone archive cannot represent.

## Authoritative sources

Nothing here was inferred from memory. The format was taken from Yomitan's own
code and reproduced with Yomitan's own libraries:

| What | Where (yomidevs/yomitan, commit `77e200428902abf4fa48284df92da7af3dcb4162`) |
| --- | --- |

## Input: the dexie-export-import document

```jsonc
{
  "formatName": "dexie",
  "formatVersion": 1,
  "data": {
    "databaseName": "dict",
    "databaseVersion": 6,            // IndexedDB version 60 / 10
    "tables": [ {"name": "dictionaries", "schema": "++,title,version", "rowCount": 2}, … ],
    "data": [
      {"tableName": "dictionaries", "inbound": false, "rows": [ {"$": [1, {…summary…}], "$types": {"$": {"": "arrayNonindexKeys"}}}, … ]},
      {"tableName": "kanji",        "inbound": false, "rows": [ … ]},
      {"tableName": "kanjiMeta",    "inbound": false, "rows": [ … ]},
      {"tableName": "media",        "inbound": true,  "rows": [ {"dictionary": "…", "path": "…", "mediaType": "image/png", "width": 64, "height": 64, "content": "<base64>", "id": 1, "$types": {"content": "arraybuffer"}}, … ]},
      {"tableName": "tagMeta",      "inbound": false, "rows": [ … ]},
      {"tableName": "termMeta",     "inbound": false, "rows": [ … ]},
      {"tableName": "terms",        "inbound": true,  "rows": [ {…term…, "id": 1, "$types": {"glossary": "arrayNonindexKeys"}}, … ]}
    ]
  }
}
```

* Tables are listed alphabetically (that is how Dexie enumerates object
  stores), so `dictionaries` always comes first. The converter uses this to
  list the dictionaries after reading only the head of the file, and rejects
  files where another Yomitan table precedes `dictionaries` (they were
  rewritten by something else).
* `inbound: true` tables (`terms`, `media`) store the primary key inside the
  row (`id`); the others store it out of line and each row is a `[key, value]`
  tuple. The key is the auto-increment id, i.e. the order in which Yomitan
  imported the rows. The `dictionaries` key order is the installation order
  that the numbered output file names preserve.
* Rows are encoded with [typeson](https://github.com/dfahlander/typeson) using
  the structured-cloning preset. The converter revives `arrayNonindexKeys`
  (identity for plain arrays), `arraybuffer` (base64), typed arrays, `blob`,
  `undef`, `nan`/`infinity`, `date` and `bigint`; anything else is rejected
  with the type name. Yomitan's data only ever contains the first two.
* The file is parsed as a stream. Only one row is held at a time, plus one
  partially filled bank (10 000 rows) per dictionary and the compressed output.

## Output: one archive per dictionary

All archives are written as **format 3** with this entry order:
`index.json`, `term_bank_N.json`, `term_meta_bank_N.json`, `kanji_bank_N.json`,
`kanji_meta_bank_N.json`, `tag_bank_N.json`, `styles.css` (if any), then media
files sorted by path. Banks hold 10 000 rows. Every byte is deterministic:
fixed DOS timestamp (1980-01-01), no extra fields, raw deflate from the pinned
`vendor/fflate.js` at level 6 for JSON/CSS, `store` for media, ZIP64 records
only when more than 65 534 entries or 4 GiB are involved.

### `dictionaries` row → `index.json`

| Stored field | Output | Notes |
| --- | --- | --- |
| `title`, `revision` | same | required |
| `version` | `format: 3` | see *format 1* below |
| `sequenced` | `sequenced` | always written as a boolean |
| `author`, `url`, `description`, `attribution`, `sourceLanguage`, `targetLanguage`, `frequencyMode`, `minimumYomitanVersion` | same | only when the summary has them as strings |
| `isUpdatable`, `indexUrl`, `downloadUrl` | same | only when all three are present (Yomitan only stores them together) |
| `styles` | `styles.css` | only when non-empty |
| `importDate`, `prefixWildcardsSupported`, `counts`, `importSuccess`, `yomitanVersion` | dropped | runtime bookkeeping, not dictionary content; `counts` is used to detect partial exports |

### `terms` row → `term_bank_N.json`

`[expression, reading, definitionTags, rules, score, glossary, sequence, termTags]`.
`expressionReverse`/`readingReverse`/`id` are derived values and are dropped.
Glossary items:

* strings pass through;
* `{"type":"image"}` objects: the importer replaced the author's
  `width`/`height` with the decoded image's pixel size and moved the originals
  to `preferredWidth`/`preferredHeight`. The converter writes
  `preferredWidth`→`width`, `preferredHeight`→`height`, drops the pixel size,
  and keeps `path`, `title`, `alt`, `description`, `pixelated`,
  `imageRendering`, `appearance`, `background`, `collapsed`, `collapsible`;
* `{"type":"structured-content"}`: the tree is copied; `img` nodes get the
  same treatment as above plus `verticalAlign`, `border`, `borderRadius`,
  `sizeUnits`;
* deinflection arrays (`["form", ["rule"]]`) and anything else pass through.

### `termMeta`, `kanjiMeta`, `kanji`, `tagMeta`

Direct inverses of the importer: `[expression, mode, data]`,
`[character, mode, data]`, `[character, onyomi, kunyomi, tags, meanings, stats]`,
`[name, category, order, notes, score]`. Frequency, pitch-accent and IPA
`data` objects are copied verbatim.

### `media`

Each row is written at its `path` with its exact bytes. Paths that are not
safe relative archive paths (`..` segments, absolute paths, backslashes,
control characters, or names that collide with bank files) are skipped with a
warning rather than written.

## Known losses and normalizations

These are inherent to the data Yomitan keeps; the converter reports the ones
it can detect in the conversion report.

| Item | Why | Effect |
| --- | --- | --- |
| Empty readings | Yomitan stores `reading = expression` when the bank had `""` | Output has the expression as the reading. Yomitan and Hachidori treat both spellings identically. |
| `{"type":"text","text":…}` glossary objects | Yomitan stores them as plain strings | Output has the string. Rendering is identical. |
| Format 1 dictionaries | Yomitan keeps no `sequence`/`termTags`/`stats` for them, and current Yomitan cannot import format 1 archives that contain glossaries at all (its v1 schemas cap rows at 5/4 items) | Written as format 3 with `sequence 0`, empty `termTags`, `stats {}`. Reported as `format-upgraded`. |
| Obsolete `index.json` `tagMeta` | Yomitan folds it into `tagMeta` rows (only when the archive also had at least one `tag_bank`) | Written as `tag_bank` rows. |
| Files in the original archive that no entry referenced (unused images, audio, `LICENSE`, `source_manifest.json`, …) | Yomitan never stores them | Not recoverable. Not detectable. |
| Image attributes Yomitan does not copy (`data`, `lang` on `img` nodes) | Dropped at import | Not recoverable. |
| Original bank boundaries, bank sizes, JSON whitespace, archive timestamps and compression | Not stored | Output uses its own canonical layout, so a converted archive is generally not byte-identical to the originally downloaded ZIP even though it contains the same dictionary. |
| Yomitan's dictionary *priority* order and per-dictionary settings | Live in the settings backup, not in the dictionary collection | The numbered file names follow installation order (the `dictionaries` table key). Re-order by name or by hand in the UI before converting. |
| Original `index.json` key order and `format` vs `version` spelling | Not stored | Output always uses `format`. |
| Custom `mediaType` for unusual image extensions | Yomitan derives it from the file name | Re-derived by the importer on the way back in. |
| Partial exports | Yomitan recorded per-table counts at import time | Mismatches are reported as `count-mismatch`; rows for unlisted dictionaries as `orphan-rows`; images referenced but missing as `media-missing`. A truncated file is rejected outright. |
| Titles containing `/` or `\` | Yomitan accepts them; Hachidori's engine refuses to create a directory for them | The archive is still valid; Hachidori will decline it. |
| Dictionaries or media larger than 4 GiB inside one archive, or more than 65 534 files | Needs ZIP64 | Written with ZIP64; Yomitan reads it. Hachidori's reader honours the ZIP64 end record (entry count) but reads 32-bit per-entry sizes, so archives with a single entry above 4 GiB would not import there. |
